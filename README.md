# Lumen RSS

[![CI](https://github.com/AyaseElibing/lumen-rss/actions/workflows/ci.yml/badge.svg)](https://github.com/AyaseElibing/lumen-rss/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
![Node](https://img.shields.io/badge/node-%3E%3D22.5-3fb950.svg)
![Dependencies](https://img.shields.io/badge/dependencies-0-3fb950.svg)

本地优先的 RSS / Atom 订阅阅读器。**零外部依赖**：不需要数据库服务、不需要构建工具、不需要 `npm install`，
只用 Node.js 内置能力（`node:sqlite` + `node:http`）和一个原生 ES Module 前端。

```bash
cd rss-reader
npm start          # 等价于 node --disable-warning=ExperimentalWarning server/index.js
# 打开 http://127.0.0.1:5178
```

macOS 上也可以直接双击 `start.command`（会自动启动服务并打开浏览器）。

> 需要 **Node.js 22.5 或更高版本** —— 依赖内置的 `node:sqlite` 模块。

首次启动会自动写入 3 个**内置示例订阅源**（覆盖 RSS 2.0 / Atom 1.0 / RSS 1.0 RDF 三种格式），
用于在完全离线的环境下立即验证完整链路。示例源可以随时在界面上删掉。

## 功能

### 订阅管理
- 添加 / 编辑 / 删除订阅源，支持 RSS 2.0、Atom 1.0、RSS 1.0 (RDF)
- **订阅地址自动发现**：直接粘贴网站首页地址，会自动扫描 `<link rel="alternate">`、常见路径
  (`/feed`、`/rss.xml`、`/index.xml`…) 找到真实订阅地址
- 分类文件夹：新建 / 重命名 / 删除（删除文件夹不会删订阅，可指定迁移目标）
- **拖拽归类**：把左侧订阅源拖到文件夹上即可
- 每源独立抓取间隔（15 分钟 ~ 24 小时）、自定义显示名、单独启用/停用
- OPML 导入 / 导出，用于备份或迁移到其它阅读器

### 抓取与更新
- 按每源间隔自动定时抓取，实际是**按 `next_fetch_at` 到期的增量调度**，不是无脑全量轮询
- 手动刷新：到期刷新 / 强制刷新（忽略缓存标记）/ 单源刷新
- 实时进度：SSE 推送抓取进度与结果，界面顶部有进度条，完成后弹出汇总

### 阅读
- 三栏布局：订阅列表 / 文章列表 / 阅读区
- 文章列表展示标题、摘要、来源、相对发布时间、未读状态点、收藏星标
- 阅读区渲染净化后的全文（含代码块、表格、引用、图片），可调正文字号（15–24px）
- 已读 / 未读标记（点开自动标记，可逐篇撤销）、收藏、在浏览器打开原文
- 智能视图：全部文章 / 未读 / 收藏；外加 全部 / 未读 / 收藏 三段式筛选
- 关键词搜索：跨标题、摘要、作者、正文，多关键词为 AND 关系，命中处高亮
- 排序：按发布时间 / 按抓取时间
- 无限滚动加载，单页 40 条
- 批量「全部标为已读」：作用于当前视图范围

## 数据一致性设计

这是本项目最花心思的部分。抓取任务天生是「至少一次」语义：超时重试、进程重启、手动刷新与定时任务撞车，
都会让同一篇文章被处理多次。为此做了四层防护：

**1. 幂等入库**
文章主键是 `sha1(feedId + guid)`，并在数据库层加 `UNIQUE(feed_id, guid)` 兜底。
同一条文章无论抓多少次都只有一行。统计「新增几篇」不能用 `changes()`（upsert 的插入与更新都返回 1），
而是在事务内对 `COUNT(*)` 取前后差值。

**2. 用户状态与抓取状态分离**
`read` / `starred` / `read_at` / `starred_at` 属于用户态，**永不出现在 upsert 的 `DO UPDATE SET` 子句中**。
源站修改标题、正文字段会被更新，但已读与收藏不会被冲掉。正文变短时保留更完整的旧正文。

**3. 单写者 + 事务**
所有多语句写入包裹在 `BEGIN IMMEDIATE` 事务里，失败整体回滚。
配合单连接同步 API，任何一段「读-改-写」都不会被其它请求插入。

**4. 重入保护**
每个源维护在途集合，同一源并发触发时后续请求直接跳过；
同一个源的定时抓取与手动刷新同时发生也只会发出一次网络请求。

其它稳定性措施：

- **双层并发限流**：全局并发上限（默认 6）+ 单域名并发上限（默认 2）。
  队列按域名择先而非严格 FIFO —— 队首域名满了会跳过它先跑后面空闲域名的任务，兼顾礼貌与吞吐。
- **条件请求**：保存 `ETag` / `Last-Modified`，304 时完全跳过解析与写库。实测绝大多数轮询什么都不会变。
- **指数退避**：连续失败的源按 `间隔 × 2^n` 放大下次抓取，封顶 24 小时；一旦成功立即清零失败计数。
- **请求超时与大小上限**：默认 20s 超时、响应体 8MB 截断，单个畸形源不会拖垮整个调度。
- **字符集嗅探**：按 `Content-Type` / XML 声明 / `<meta charset>` 推断编码，GBK 中文源不会乱码。
- **保留策略**：单源最多保留 1500 篇，只裁剪「已读且未收藏」的旧文，未读与收藏永不丢弃。
- **抓取结果局部化**：单个源失败只记录错误状态，批次继续推进并汇总上报，不会因为一个坏源中断更新。

## 安全

订阅源正文来自任意第三方站点，且会被插入到页面中，因此阅读区渲染走**白名单净化**：

- 只用明确安全的标签（`p` / `h1-6` / `ul` / `pre` / `code` / `table` / `img` / `a` …）
- 真正危险的容器（`script` / `style` / `iframe` / `object` / `form` / `svg` / `template`…）**整块移除**
- 非白名单标签「解包」而非删除，避免丢正文
- 所有 `on*` 事件属性与 `style` 内联样式一律不保留
- 链接协议白名单（`http(s)` / `mailto` / 相对路径），`javascript:`、`vbscript:`、`data:text/html` 全部拦截
- 外链强制 `rel="noopener noreferrer nofollow"`，图片加 `referrerpolicy="no-referrer"` 规避追踪像素
- 输入长度与节点数双重上限，防止 DOM 膨胀

服务默认只监听 `127.0.0.1`，数据全部保存在本机 `data/lumen.sqlite`，不外发任何数据。
阅读器不会向第三方图标服务请求 Favicon —— 只使用订阅源自带的图标地址，避免泄露订阅清单。

## 常见问题

**抓取失败怎么办？**
鼠标悬停左侧订阅源名称可看到具体错误。检查：地址是否需要科学上网、站点是否已停止服务、
是否被目标站点的反爬策略拦截（可调小「同一域名并发上限」为 1）。连续失败的源会自动退避，不会持续请求。

**端口被占用？**
`npm start -- --port 5180`。

**数据在哪？怎么备份？**
整个订阅库就是 `data/lumen.sqlite` 一个文件（含 WAL）。用界面上的「导入 / 导出 OPML」可以只导出订阅清单；
直接复制 sqlite 文件则是完整备份（含已读与收藏状态）。

**能多设备同步吗？**
本应用是本地优先的单机设计。可以把 `--data-dir` 指向网盘目录，或自行用 OPML 迁移订阅清单。
